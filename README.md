# 🎓 Student Management REST API

A backend REST API built with **Java + Spring Boot** for managing student records.

This project is being developed as a hands-on learning project while learning backend development, REST APIs, Spring Boot, JPA/Hibernate, PostgreSQL, validation, DTOs, and API error handling.

## 🏗️ Project Architecture

The application follows a layered backend architecture:

```text
Client
   ↓
Controller
   ↓
DTO + Validation
   ↓
Service
   ↓
Repository
   ↓
JPA / Hibernate
   ↓
PostgreSQL
```

### Main Components

**Controller**
Handles HTTP requests and responses.

**DTO**
Controls the data accepted from API clients and handles request validation.

**Service**
Contains the application's business logic.

**Repository**
Handles communication with the database through Spring Data JPA.

**Entity**
Represents the `Student` table in PostgreSQL.

**Exception Handler**
Provides consistent responses for errors such as missing students and invalid request data.

## 📚 Current Features

### ✅ Create Student

```http
POST /students
```

Example request:

```json
{
    "name": "Michael",
    "age": 23,
    "course": "Cyber Security",
    "active": true
}
```

The student ID is automatically generated by PostgreSQL.

Example response:

```json
{
    "id": 1,
    "name": "Michael",
    "age": 23,
    "course": "Cyber Security",
    "active": true
}
```

Returns:

```text
201 Created
```

---

### ✅ Get All Students

```http
GET /students
```

Returns all students stored in the database.

Returns:

```text
200 OK
```

---

### ✅ Get Student By ID

```http
GET /students/{id}
```

Example:

```http
GET /students/1
```

Returns:

```text
200 OK
```

If the student does not exist:

```text
404 Not Found
```

Example:

```json
{
    "message": "Student with ID 99 not found"
}
```

---

### ✅ Update Student

```http
PUT /students/{id}
```

The API finds the existing student, updates the supplied information, and saves the changes.

Returns:

```text
200 OK
```

---

### ✅ Delete Student

```http
DELETE /students/{id}
```

Successfully deleting a student returns:

```text
204 No Content
```

---

## 🛡️ Validation

Student creation requests are validated using Jakarta Bean Validation.

Current rules include:

* Name cannot be blank
* Course cannot be blank
* Age must be at least 18

Example invalid request:

```json
{
    "name": "",
    "age": 17,
    "course": "",
    "active": true
}
```

The API returns:

```text
400 Bad Request
```

Example response:

```json
{
    "name": "Name cannot be blank",
    "course": "Course cannot be blank",
    "age": "Age must be at least 18"
}
```

---

## ⚠️ Exception Handling

The API uses a global exception handler to provide cleaner error responses.

Currently handled:

* Student not found → `404 Not Found`
* Validation errors → `400 Bad Request`

## 🗄️ Database

The application uses PostgreSQL.

Database:

```text
student_db
```

Table:

```text
student
```

Student fields:

| Field  | Type    | Description                         |
| ------ | ------- | ----------------------------------- |
| id     | Long    | Automatically generated primary key |
| name   | String  | Student name                        |
| age    | int     | Student age                         |
| course | String  | Student's course                    |
| active | boolean | Student status                      |
